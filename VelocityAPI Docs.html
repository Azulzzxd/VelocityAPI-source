Velocity public-API

A .NET 10 class library for attaching to Velocity-enabled processes, sending Lua scripts to them over a named pipe, and validating a Velocity license key.

Requirements & setup

Everything you need installed, and how to add VelocityAPI to a project using the Visual Studio UI.

Required dependencies

DependencyDetails
Windows 10 / 11 (x64)The library calls Windows-only APIs and will not run on Linux or macOS.
.NET 10 SDK (runtime for end users)The project targets net10.0. For a WPF or WinForms app, target net10.0-windows.
Visual StudioA version that supports .NET 10 and the .slnx solution format (the source was authored in Visual Studio 2026). Install the .NET desktop development workload.
BouncyCastle NuGet packageVersion 1.8.9, as referenced by VelocityAPI.csproj. Ships BouncyCastle.Crypto.dll, which must sit next to your app.
Administrator rightsThe injector requires elevation. Restart Visual Studio as administrator to debug.
Internet accessrealvelocity.xyz (auto-update on StartCommunication) and getvelocity.llc (license auth).

The following ship with .NET and need no extra install: System.Net.Http, System.Text.Json, System.IO.Pipes, System.Security.Cryptography, Microsoft.Win32.Registry.

No prebuilt DLL on the repo The source repository does not distribute compiled DLLs. Build VelocityAPI yourself, or use a DLL you already have.

1. Build the DLL

  1. Open VelocityAPI.slnx in Visual Studio.
  2. In the toolbar set the configuration to Release.
  3. Choose Build → Build Solution (Ctrl+Shift+B).
  4. Your output is in VelocityAPI\bin\Release\net10.0\: VelocityAPI.dll and BouncyCastle.Crypto.dll.

2. Add it to your project (Visual Studio UI)

Option A: reference the DLL

  1. In Solution Explorer, right-click your project's Dependencies node and choose Add Project Reference…
  2. Open the Browse tab and click Browse… at the bottom.
  3. Select VelocityAPI.dll and click Add, then OK.
  4. Expand Dependencies → Assemblies, select VelocityAPI, and in the Properties window set Copy Local to Yes.

Option B: reference the project

  1. Right-click the solution → Add → Existing Project… and pick VelocityAPI\VelocityAPI.csproj.
  2. Right-click your project's Dependencies → Add Project Reference… → Projects → tick VelocityAPI → OK.

Option B also brings in BouncyCastle automatically. With Option A you must add it yourself:

  1. Right-click your project → Manage NuGet Packages…
  2. On the Browse tab search for BouncyCastle, pick version 1.8.9, click Install.

The same result as a project file entry:

<ItemGroup>
  <Reference Include="VelocityAPI">
    <HintPath>libs\VelocityAPI.dll</HintPath>
    <Private>True</Private>
  </Reference>
  <PackageReference Include="BouncyCastle" Version="1.8.9" />
</ItemGroup>
Reference it, don't embed it Do not set the DLL's Build Action to Embedded Resource. .NET resolves referenced assemblies from the output folder, so the DLL (and BouncyCastle.Crypto.dll) must be copied next to your .exe. Use Copy Local = Yes, or Copy to Output Directory = Copy always if you added the file as an item.

3. Require administrator

  1. Right-click your project → Add → New Item…
  2. Choose Application Manifest File (Windows) and keep the name app.manifest.
  3. In the file, set the execution level:
<requestedExecutionLevel level="requireAdministrator" uiAccess="false" />

Windows now shows a UAC prompt every time the app starts. After this change, restart Visual Studio as administrator to build and debug. Confirm the manifest is picked up under Project → Properties → Application → Win32 resources → Manifest.

4. Hook up start and stop (WPF)

  1. Open your window in the designer and click it. In the Properties window switch to Events (the ⚡ icon).
  2. Double-click the Loaded field and again on Closing. Visual Studio creates both handlers.
  3. Fill them in as shown in the Quickstart.

5. Files created at runtime

Everything is relative to the app's current working directory (normally the folder containing your .exe):

Quickstart

A complete WPF example: start the service, attach to a process, execute a script, clean up.

Complete the setup first (reference, BouncyCastle, administrator manifest).

1. Create the instance

Keep one VelAPI per app, at class level.

using VelocityAPI;

public partial class MainWindow : Window
{
    private readonly VelAPI velocityApi = new VelAPI();

2. Start and stop

    private async void Window_Loaded(object sender, RoutedEventArgs e)
    {
        // Blocking network + file work (auto-update), so keep it off the UI thread.
        await Task.Run(() => velocityApi.StartCommunication());
    }

    private void Window_Closing(object sender, System.ComponentModel.CancelEventArgs e)
    {
        velocityApi.StopCommunication();
    }

3. Attach to a process

    private async Task<bool> AttachAsync(int pid)
    {
        VelocityStates state = await velocityApi.Attach(pid, 15000);
        return state == VelocityStates.Attached;
    }

4. Execute a script

    private void RunScript(string lua, int pid)
    {
        VelocityStates result = velocityApi.Execute(lua, new[] { pid });

        if (result == VelocityStates.NotAttached)
            MessageBox.Show("Attach first.");
    }
}

5. Check the result

CallYou can get
AttachAttached or Error (timeout)
ExecuteExecuted or NotAttached

See VelocityStates for details.

Offline start StartCommunication contacts the update server first. If it cannot be reached the call throws, so wrap it in try/catch in production code.

VelAPI

public class VelocityAPI.VelAPI. The main entry point: tracks attached processes and sends Lua scripts to them.

Constructor

public VelAPI()

Creates an instance. Nothing starts until you call StartCommunication().

Public fields

public VelocityStates VelocityStatus = VelocityStates.NotAttached

The last state set by Attach: Attaching while waiting, then Attached or Error.

public List<int> injected_pids

Process IDs currently tracked as attached. The library mutates it under an internal lock that is not exposed, so avoid iterating it from your own threads. Use IsAttached and AttachedCount instead.

Properties

public int AttachedCount { get; }

Number of clients whose Lua pipe currently exists. Dead entries are pruned first.

Methods

public void StartCommunication()

Prepares the working folder, updates the helper binaries and starts the background service.

  1. Creates Bin, AutoExec, Workspace and Scripts if missing.
  2. Auto-update. Reads download_links.json and current_version.txt from realvelocity.xyz. If the version differs from Bin\current_version.txt, it deletes and re-downloads Bin\erto3e4rortoergn.exe (the injector) and Bin\Decompiler.exe.
  3. Calls StopCommunication(), then starts Bin\Decompiler.exe hidden, with redirected input, output and error.
  4. Starts a 100 ms timer that prunes detached clients and sends every attached client setworkspacefolder: <cwd>\Workspace (Base64).

This call is synchronous and blocks on network I/O. It throws if the update server is unreachable.

public void StopCommunication()

Stops the timer, kills and disposes the Decompiler.exe process and clears injected_pids. Call it when your app closes. Safe to call repeatedly.

public Task<VelocityStates> Attach(int pid, int timeoutMs = 15000)

Attaches to the process with ID pid.

ParameterTypeDescription
pidintTarget process ID.
timeoutMsintOptional. How long to wait for the client's pipe to appear. Default 15000.

Behaviour

  • If the pipe for pid already exists, returns Attached immediately.
  • Otherwise sets VelocityStatus = Attaching and launches Bin\erto3e4rortoergn.exe <pid> (a visible console window; it does not wait for it to exit).
  • Polls every 100 ms for the pipe. When it appears, the PID is tracked and Attached is returned.
  • If the timeout passes, returns Error.

Returns Attached or Error. Bin\erto3e4rortoergn.exe must exist, so call StartCommunication first.

public bool IsAttached(int pid)

Checks whether the Lua pipe for pid exists. If it does, the PID is added to the tracked list (if not already there) and true is returned. If not, the PID is removed and false is returned. Detection is purely pipe-based, so it also finds clients attached by other means.

public VelocityStates Execute(string script, IEnumerable<int> targetPids)

Sends a Lua script to every listed PID that is attached.

ParameterTypeDescription
scriptstringLua source. It is Base64-encoded (UTF-8) before sending.
targetPidsIEnumerable<int>Processes to run in. PIDs failing IsAttached are skipped.

Returns NotAttached if no PID is attached, otherwise Executed.

"Executed" means "sent"The script is written to each pipe on a background thread (fire and forget). Script errors and output are not returned.
public static bool SaveLicenseKeyToRegistry(string key)

Creates HKEY_CURRENT_USER\SOFTWARE\Velocity if needed and writes the trimmed key as two REG_SZ values: LicenseKey and RBX_EXT_LicenseKey.

Returns false for null, empty or whitespace keys or on any registry error, otherwise true. See Licensing for how to read it back.

public static string Base64Encode(string plainText)

UTF-8 bytes of plainText, Base64-encoded.

public static byte[] Base64Decode(string plainText)

Decodes a Base64 string to bytes. Throws FormatException on invalid input. The parameter is Base64 text despite its name.

VelocityStates

public enum VelocityAPI.VelocityStates. The result of attach and execute operations.

public enum VelocityStates
{
    Attaching,      // 0
    Attached,       // 1
    NotAttached,    // 2
    NoProcessFound, // 3
    TamperDetected, // 4
    Error,          // 5
    Executed        // 6
}
ValueUsed byMeaning
AttachingVelocityStatusAn attach is waiting for the pipe.
AttachedAttachThe client's pipe exists; ready for scripts.
NotAttachedExecute, default VelocityStatusNo listed PID is attached.
NoProcessFoundnot usedDefined but never returned by VelAPI in this version.

Licensing

The Velocity namespace contains VelocityLicense, which validates a license key against the Velocity server.

Where the key is stored

The license key lives in the registry of the current Windows user:

Computer\HKEY_CURRENT_USER\SOFTWARE\Velocity\LicenseKey   [REG_SZ]

VelAPI.SaveLicenseKeyToRegistry also writes the same value to RBX_EXT_LicenseKey. Read it like this:

using Microsoft.Win32;

static string? ReadLicenseKey()
{
    using RegistryKey? rk = Registry.CurrentUser.OpenSubKey(@"SOFTWARE\Velocity");
    return rk?.GetValue("LicenseKey") as string;   // null if not set
}

To check it by hand, open regedit and go to the path above. The value type is String.

Accepted key formats

AuthenticateAsync rejects anything else locally with "bad key format".

KindFormat
Paid personalV****-****-****-****: 20 characters, uppercase hex, e.g. VABCD-1234-EF56-7890
Work.ink free key64 lowercase hex characters
Admin shared key3 to 32 characters from A-Z a-z 0-9 _ -

VelocityLicense

public sealed class Velocity.VelocityLicense : IDisposable

public VelocityLicense()

Creates the client for https://getvelocity.llc (browser-style User-Agent, JSON accept header).

public bool IsAuthenticated { get; }

true after a successful AuthenticateAsync.

public Task<AuthResult> AuthenticateAsync(string key)

Authenticates key and opens an encrypted session.

  1. Validates the key format.
  2. Computes the hardware ID (details). Fails with "hwid failed" if empty.
  3. Generates an ephemeral X25519 key pair, derives a transit key from the server's public key (HKDF), and sends the encrypted request to POST /api/v1/license/auth with the key, hardware IDs and product "roblox".
  4. On a TIMESTAMP_SKEW reply, adjusts for the server clock and retries once.

Returns AuthResult. On failure Error holds the reason, e.g. bad key format, hwid failed, server: …, no valid response after retry, response decrypt failed.

public Task<LicenseStatus?> QueryStatusAsync()

Asks the server how long the authenticated key has left (POST /api/v1/license/status, encrypted with the session key).

Returns null if you have not authenticated, or on a network, server (5xx) or decrypt failure. On an HTTP 4xx the result has only Code set. Otherwise a fully populated LicenseStatus.

public void Dispose()

Clears the authenticated state, zeroes the session key and disposes the HttpClient. Use using var.

Example

using Velocity;
using VelocityAPI;

string? key = ReadLicenseKey();                       // from HKCU\SOFTWARE\Velocity\LicenseKey
if (key is null) { Console.WriteLine("No key saved."); return; }

using var license = new VelocityLicense();

VelocityLicense.AuthResult auth = await license.AuthenticateAsync(key);
if (!auth.Ok) { Console.WriteLine($"Auth failed: {auth.Error}"); return; }

VelocityLicense.LicenseStatus? status = await license.QueryStatusAsync();
if (status is null) { Console.WriteLine("Status query failed."); return; }

if (status.SecondsRemaining < 0)
    Console.WriteLine("Lifetime key");
else
    Console.WriteLine($"Expires in {status.SecondsRemaining}s ({status.Duration})");

VelAPI.SaveLicenseKeyToRegistry(key);                 // persist for next launch

Helper types

Smaller public types in the assembly.

AESEncryption

public class AESEncryption (global namespace). Password-based AES-GCM through Windows CNG (bcrypt.dll). The key is derived from the password with PBKDF2-SHA256 and a random salt.

public static string Encrypt(string plaintext, string password)

Returns Base64 of salt (16) ‖ nonce (12) ‖ ciphertext ‖ tag. Throws ArgumentException if plaintext or password is empty. The output differs on every call because salt and nonce are random.

public static string Decrypt(string ciphertext, string password)

Reverses Encrypt. Throws ArgumentException for empty input, an error for data that is too short, and a cryptographic error with "Wrong password or corrupted data" on a bad password or tampered data.

string sealedText = AESEncryption.Encrypt("secret", "hunter2");
string plain      = AESEncryption.Decrypt(sealedText, "hunter2");

The library itself uses this to decrypt the download links during auto-update.

Internals & data use

What the library does behind the public API. Read this before shipping an app that uses it.

Named pipes

Each attached client exposes a pipe named uoQcySKXSUxxJNpVQyatpHQwYoGfhcbh_<pid>, reachable as \\.\pipe\uoQcySKXSUxxJNpVQyatpHQwYoGfhcbh_<pid>. Existence is tested with WaitNamedPipe; this is the only attach detection. Scripts are written to the pipe as Base64 text from a short-lived background thread. Errors are swallowed.

Network access

HostWhenWhat
realvelocity.xyzStartCommunicationassets/current_version.txt and assets/download_links.json, then the two executables if the version changed.
getvelocity.llcAuthenticateAsync, QueryStatusAsyncEncrypted license requests.

Hardware ID

Data sent to the license server The hardware ID is a 32-byte HKDF hash (hex) of the Windows MachineGuid, the CPU vendor string and feature flags, the system volume serial, and the SMBIOS system UUID. A legacy ID, identical but using the network adapter MAC address instead of the SMBIOS UUID, is also sent when it differs. Mention this in your privacy notice if you distribute software that calls AuthenticateAsync.

Auto-update

Downloads and runs executables StartCommunication may replace Bin\Decompiler.exe and Bin\erto3e4rortoergn.exe with files fetched from the update host, then launches them (the injector one on Attach, with administrator rights). Only use it where that is acceptable, and keep your app's working directory writable only by trusted users.

License wire format

Requests are JSON envelopes {"v":1, ...} carrying an AES-256-GCM payload (iv(12) ‖ tag(16) ‖ ciphertext, hex-encoded). The additional authenticated data binds the timestamp and nonce, and replies use a |resp suffix. A server-reported clock skew is corrected once per call.
